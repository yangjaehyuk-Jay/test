# 은행연합회 파생상품 정보 일일 조회

`bizinfo.kfb.or.kr` (은행연합회 통합업무시스템)에서 약 60개 기업의
파생거래 정보를 매일 조회해 엑셀로 저장한다.

## 사용법

```
cd "C:\Users\infomax\Documents\클로드\KFB_파생거래"
python scrape.py
```

1. 브라우저가 열리면 **로그인** (ID/PW + 추가 인증)
2. 로그인이 끝나면 우측 하단 **`▶ 자동 조회 시작`** 버튼이 파랗게 켜진다
3. 버튼을 누르면 `companies.csv` 의 기업을 차례로 조회한다
4. 끝나면 `output/파생거래_YYYYMMDD.xlsx` 저장

옵션:

```
python scrape.py --from 20260101 --to 20260828   # 조회기간 (기본: 올해 1월 1일 ~ 오늘)
python scrape.py --delay 4                        # 요청 간격 초 (기본 2.5)
python scrape.py --companies companies1.csv       # 다른 목록으로 조회
```

### 목록이 여럿일 때

`--companies` 로 다른 목록 파일을 준다. **결과 파일 이름에 목록 번호가 붙으므로
서로 덮어쓰지 않는다.**

| 목록 | 명령 | 결과 |
|---|---|---|
| `companies.csv` (98개) | `python scrape.py` | `output/파생거래_YYYYMMDD.xlsx` |
| `companies1.csv` (60개) | `python scrape.py --companies companies1.csv` | `output/파생거래1_YYYYMMDD.xlsx` |

꼬리표는 파일명에서 `companies` 뒤를 그대로 떼어 쓴다 (`companies1.csv` -> `1`).
중간 저장 파일도 같은 규칙이다 (`_진행중1_YYYYMMDD.csv`). 두 목록은 각각 따로
실행한다 — 한 번에 둘 다 돌지는 않는다. 시트 구성·서식·합계 열은 목록과 무관하게 같다.

`companies1.csv` 는 조선·기자재·전선·화장품·플랫폼 등 60개 상장사다. 사업자등록번호는
DART 전자공시 기업개황(`company.json` 의 `bizr_no`)에서 받아왔고 (2026-09-01 기준),
60건 모두 검증코드가 맞고 중복이 없다. 둘째 열에 기업명을 메모로 넣어두었으므로
로그와 엑셀 `메모` 열에서 어느 회사인지 바로 보인다.

조회 대상은 `companies.csv` 에 한 줄에 하나씩. 하이픈은 있어도 없어도 된다.
열은 **`사업자등록번호,기업명,분류`** 세 개다. 뒤의 둘은 없어도 되고, 있으면 합쳐져
`메모` 가 된다 (`삼양사(주) (GC)`). 엑셀 `메모` 열과 실행 로그에 그대로 나온다.

```
101-86-66838,삼양사(주),GC
4548703296,삼양바이오팜,GC
"104-81-25433","영신쿼츠(주)",JC
```

기업명에 쉼표가 들어가면(`LG CHEM, LTD.`) 큰따옴표로 감싼다. 프로그램이 CSV 로 읽으므로
엑셀에서 저장해도 그대로 유지된다.

**기업명 출처.** 되도록 DART 전자공시 기업개황의 정식명을 넣되, **사업자등록번호가
정확히 일치할 때만** 채택했다. 이름만 비슷해서 넣은 값은 없다. 확인이 안 된 곳은
KFB 조회 응답이 준 기업명(`KIKO_CUST_NM`)을 그대로 뒀는데, 이 값은 **15자에서 잘려서
온다** (`AMKOR TECHNOLOG`, `HYNIX SEMICONDU`). 잘린 이름이라도 조회에는 영향이 없다 —
조회는 사업자등록번호로만 하고, 기업명은 사람이 알아보기 위한 것이다.

`012-40-11628` 한 줄은 이름이 비어 있다. 검증코드가 맞지 않고 조회도 `401` 로 와서
확인할 방법이 없다. 원본 번호를 다시 확인하는 편이 좋다.

**선행 0**: 엑셀은 `0124011628` 을 숫자로 보고 앞의 `0` 을 떼어 `124011628` 로
저장한다. 이래서 예전에는 "10자리 아님"으로 건너뛰었다. 지금은 8~9자리로 들어온
값은 앞을 `0` 으로 채워 10자리로 복원한다 (실행 시 `선행 0 복원: ...` 로그가 뜬다).
엑셀에서 직접 관리한다면 해당 열을 **텍스트 서식**으로 두는 편이 안전하다.

**검증코드 확인**: 읽어들일 때 사업자등록번호 검증코드(마지막 자리)를 계산해본다.
맞지 않으면 로그에 `N행 경고: 검증코드 불일치 ...` 를 남긴다. **경고일 뿐 걸러내지는
않는다** — 그런 번호도 그대로 조회하고 결과에도 포함시킨다. 번호가 틀렸으면 보통
`401` 이나 `ERR` 로 돌아오므로, 경고가 뜬 행의 결과를 보고 원본을 확인하면 된다.

## 알아낸 API

캡처(`capture_login.py`)로 확인한 실제 통신 구조.

### 조회

```
POST https://bizinfo.kfb.or.kr/bizkiR0101SelectList.do
Content-Type: text/xml
```

요청 `ds_search` (1행):

| 컬럼 | 값 |
|---|---|
| `USER_ID` / `USER_NM` | 로그인 사용자 |
| `USER_ORG_CD` / `USER_ORG_NM` | 소속 기관 |
| `KIKO_ID_NO_TP_CD` | `2` = 사업자등록번호 (`1` = 주민등록번호) |
| `KIKO_ID_NO` | **`"999"` + 사업자등록번호 10자리** (13자리 조회요청 식별번호) |
| `INQ_DV_CD` | `1` |
| `INQ_ST_DT` / `INQ_ED_DT` | 조회기간 `YYYYMMDD` |
| `IS_IN_USER` | `N` |

`USER_*` 네 개는 로그인 응답 `bizliS0102Login2.do` 의 `ds_list` 에서 그대로 나온다.
스크립트가 로그인 응답을 엿들어 자동으로 채운다.

응답 `ds_etc` (조회 상태):

| 컬럼 | 뜻 |
|---|---|
| `RSP_CD` / `RSP_NM` | `000` 정상 / `401` 조회 해당자료 없음 |
| `KIKO_CUST_NM` | 기업명 (전각문자로 옴 → NFKC 정규화함) |
| `KIKO_ID_NO` | 사업자번호 (하이픈 포함) |
| `RETRIEVE_DTTM` | 조회 시각. 엑셀에서는 `조회일자` / `조회시각` 두 열로 나뉜다 |
| `BNS_AMT_USD_CVT_AMT` | USD 환산금액 |

응답 `ds_list` (실제 잔액. 접두어 = 상품군):

- `FX_*` 선물환 &nbsp; `OP_*` 옵션 &nbsp; `CRS_*` 통화스왑
- `_VLD_CNT` 유효건수, `_BUY_BAL` / `_SELL_BAL` 매수·매도 잔액,
  `_TRN_LST_UPD_DT` 최종갱신일
- 옵션만 세분: `OP_BUY_CALL_BAL`, `OP_BUY_PUT_BAL`,
  `OP_SELL_CALL_BAL`, `OP_SELL_PUT_BAL`

### 감사로그

```
POST https://bizinfo.kfb.or.kr/bizcmEventLoggerInsert.do
ds_log: USER_ID, USER_NM, SCREEN_ID=/BIZKI/BIZKI_R0101,
        SCREEN_NM=파생상품(TAB_01), ACT_NM=화면오픈|내역조회
```

사이트가 조회 이력을 남기는 호출이다. **자동 조회도 이걸 똑같이 보낸다.**
화면으로 조회할 때와 감사 흔적을 동일하게 유지하기 위해서다.

## 왜 이런 구조인가

| 항목 | 내용 |
|---|---|
| 화면 기술 | Nexacro 14 HTML5. 데이터는 평문 XML 데이터셋 |
| 조회 화면 | **별도 팝업 창**. 반드시 사이트 메뉴로만 열린다 (아래 참고) |
| 로그인 | ID/PW + 추가 인증 → 무인 자동화 불가. 사람이 1회 로그인 |
| 세션 | 화면에 "20분 후 자동 로그아웃" 표시 |
| 서버 | **연속 요청을 차단한다.** 막히면 XML 대신 236바이트 안내 HTML이 온다 |
| 필수 프로그램 | nProtect Online Security, MarkAny e-PageSafer (이 PC 설치완료) |

### 조회 화면은 URL 로 직접 열 수 없다

`popup.html?formname=BIZKI::BIZKI_T0101.xfdl&framename=KI01_BIZKI_T0101.xfdl` 을
브라우저에 그냥 붙여넣으면 창은 뜨지만 곧바로 죽는다.

```
Cannot read properties of undefined (reading 'KI01_BIZKI_T0101.xfdl')
Cannot read properties of null (reading '_linked_window')
```

Nexacro 팝업은 부모 앱이 먼저 팝업 프레임을 등록해야 열린다.
URL 만 여는 방식은 그 등록을 건너뛰므로 프레임과 부모 연결을 못 찾는다.
**조회 화면이 필요하면 사이트 메뉴로 열어야 한다.**

다만 `scrape.py` 는 이 화면을 열지 않는다. 화면이 보내는 XML 요청을
직접 보내기 때문에 팝업이 떠 있든 말든 상관없다.

화면을 클릭해서 긁지 않는다. Nexacro 그리드는 DOM이 수시로 바뀌어 취약하다.
대신 화면이 쓰는 XML 요청을 그대로 보낸다.

요청 간 기본 2.5초를 쉬고, 실패하면 8초 → 16초로 물러서며 3회까지 재시도한다.
56개 기업이면 감사로그 호출까지 합쳐 대략 5~6분 걸린다.

## 파일

| 파일 | 역할 |
|---|---|
| `scrape.py` | **본 프로그램.** 로그인 대기 → 일괄 조회 → 엑셀 저장 |
| `companies.csv` | 조회 대상 사업자등록번호 목록 (기본) |
| `companies1.csv` | 2차 조회 대상 60개 상장사 (`--companies` 로 지정) |
| `nexacro.py` | Nexacro XML 요청 생성 / 응답 파싱 |
| `capture_login.py` | 통신 캡처·진단 도구. API가 바뀌었을 때 다시 뜯어볼 용도 |
| `output/` | 결과 엑셀 (`파생거래_YYYYMMDD.xlsx`, `파생거래1_YYYYMMDD.xlsx`) |
| `logs/` | 실행 로그 |
| `browser_profile/` | 로그인 세션. **외부 공유 금지** |

엑셀은 3개 시트다. `파생거래`(결과), `조회정보`(조회일시·기간·성공/실패 수),
`실패`(실패한 기업과 사유. 실패가 있을 때만).

**`파생거래` 시트에는 조회에 실패한 기업도 들어간다.** `companies.csv` 의 순서와
건수가 그대로 유지되므로 원본 목록과 행을 맞춰 대조할 수 있고, 조회가 안 된 기업이
조용히 빠지지 않는다. 실패 행은 `결과코드` 가 `ERR` 이고 `결과내용` 에 사유가 적힌다
(사유 전문과 메모는 `실패` 시트에도 따로 남는다).

| `결과코드` | 뜻 |
|---|---|
| `000` | 정상. 자료 있음 |
| `401` | 서버 정상 응답. 그 기업은 해당 자료가 없다 |
| `ERR` | 조회 자체가 실패 (차단·세션만료·통신오류). `결과내용` 에 사유 |

`000` 이 아닌 행은 회색으로 흐리게 표시된다.

`파생거래` 시트 **맨 끝 두 열**은 합계다.

| 열 | 계산 |
|---|---|
| `선물환+스왑+옵션콜_매수잔액(USD mn)` | (`선물환_매수잔액` + `통화스왑_매수잔액` + `옵션_매수콜`) ÷ 1,000,000 |
| `선물환+스왑+옵션풋_매도잔액(USD mn)` | (`선물환_매도잔액` + `통화스왑_매도잔액` + `옵션_매수풋`) ÷ 1,000,000 |

**옵션은 매수 포지션만 넣는다.** 매수콜은 사실상 매수 포지션이라 매수 쪽에,
매수풋은 매도 포지션이라 매도 쪽에 더한다. **매도콜·매도풋은 어느 쪽에도 안 넣는다.**
옵션 잔액이 없는 기업은 그 항목이 `0` 이라 합계가 예전과 같다.

**결과가 없는 행(`401`·`ERR`)은 숫자 대신 `붙이지 마시오` 가 들어간다.**
`0` 으로 두면 다른 표에 옮겨 붙일 때 잔액이 정말 `0` 인 기업과 구별이 안 된다.
문구는 `NO_RESULT_TEXT` 에서 바꾼다.

> **결과코드 주의.** 엑셀을 거치면 `'000'` 이 숫자 `0` 으로 바뀐다. 그대로 두면
> 정상 행이 전부 '결과 없음' 으로 잡히므로, 읽어들일 때 `norm_rspcd()` 로
> 3자리 문자열로 되돌린다.

**단위는 USD 백만.** 서식만 바꾼 게 아니라 값 자체를 나눠 넣으므로 정렬·필터·차트가
표시 단위와 어긋나지 않는다. 소수점 두 자리까지 보인다 (`171,918,752` -> `171.92`).
가운데 개별 잔액 열(선물환·옵션·통화스왑)은 원 단위 그대로다.

한쪽만 값이 있으면 그 값이 그대로 들어가고, 양쪽 다 비면 빈 칸으로 둔다
(0 으로 채우지 않는다). 더할 열은 `scrape.py` 의 `SUMCOLS`,
단위는 `SUM_UNIT`, 표시 자릿수는 `FMT_MN` 에서 고친다.

### 서식

| 항목 | 처리 |
|---|---|
| 잔액·금액 | `#,##0` — **1의 자리까지**. 소수점은 보이지 않는다 |
| 합계 두 열 | `#,##0.00` — USD 백만 단위라 소수점 두 자리 |
| 건수 | `#,##0` |
| 값이 `0` | `-` 로 표시. 0 이 많아 눈이 미끄러지는 걸 막는다 |
| 음수 | 빨간색 |
| 머리글 | 남색 배경 + 흰 굵은 글씨, 가운데 정렬, 두 줄 줄바꿈 |
| 합계 두 열 | 초록 머리글 + 연초록 배경 + 굵은 글씨로 구분 |
| 줄무늬 | 짝수 행 연회색 |
| 묶음 구분선 | 선물환 / 옵션 / 통화스왑 / USD / 합계 시작 열 왼쪽에 굵은 선 |
| 틀 고정 | `기업명` 까지. 오른쪽으로 밀어도 어느 회사인지 보인다 |
| 자동 필터 | 머리글 행 전체 |
| `결과코드 != 000` 행 | 회색으로 흐리게 |
| `최종갱신일` 이 `0000-00-00` | 빈 칸으로 (자료 없음이라는 뜻) |
| `조회일시` | `조회일자` / `조회시각` 두 열로 나눠서 쓴다 |

숫자 열은 이름이 아니라 **응답 키**(`_BAL` / `_CNT` / `_AMT`)로 고른다.
이름으로 "잔액"만 찾으면 `옵션_매수콜`(`OP_BUY_CALL_BAL`) 처럼 '잔액'이 안 붙은
네 개 열이 문자열(`"345,800,099.04"`)로 남아 계산도 정렬도 안 된다.

**셀에는 원래 값이 그대로 있다.** 소수점은 보이지 않을 뿐 반올림해 저장하지 않으므로
합계·검산에는 영향이 없다. 서식은 `format_grid()` / `format_plain()` 에 모아뒀고
색은 `C_HEAD`, `C_BAND` 같은 상수로 뺐다.

## 문제가 생기면

먼저 `logs/scrape_*.log` 를 본다.

| 증상 | 원인 |
|---|---|
| `XML 아님 (차단 추정)` | 서버가 막았다. `--delay 5` 로 늘린다 |
| 버튼이 안 켜짐 | 로그인 응답을 못 봤다. 로그아웃 후 다시 로그인 |
| `결과코드 401` | 정상 동작. 그 기업은 해당 자료가 없다. 다만 `검증코드 불일치` 경고가 함께 떴다면 번호 오타를 의심한다 |
| 대량 실패 | 세션 만료 가능성. 다시 실행해 재로그인 |

중간에 끊겨도 `output/_진행중_YYYYMMDD.csv` (`--companies companies1.csv` 면
`_진행중1_YYYYMMDD.csv`) 에 조회한 만큼 이미 저장돼 있다.

API 자체가 바뀐 것 같으면 `python capture_login.py` 로 다시 캡처해서
`.do` 호출 요약을 비교한다.
